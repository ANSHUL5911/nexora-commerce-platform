## 1. Executive Summary

Phase 07.14 executed the complete migration of the Nexora frontend from legacy API contracts (`/api/cart-items`, `/api/delivery-options`, `/api/payment-summary`, mock card payments) to the authoritative, frozen backend contracts implemented in Phases 07.0–07.13.

### Absolute Invariants Preserved
- **Zero Backend Changes**: Backend routes, controllers, services, models, migrations, and database schemas remained 100% untouched.
- **Three-Layer Monetary Separation**: Integer paise maintained across DB, API DTOs, and formatters (`formatMoney(paise)` formats to INR `₹`).
- **Unified Checkout & Razorpay Boundary**:
  - `POST /api/checkout/initiate`: Creates `Order` (status `PENDING_PAYMENT`), reserves inventory, returns order and optional `guestToken`.
  - `POST /api/payments/create-order`: Creates `PaymentAttempt` and `Razorpay Order`.
  - `POST /api/payments/retry`: Creates subsequent `PaymentAttempt` and `Razorpay Order` on the *same* Order.
  - `POST /api/payments/verify`: Handles client verification and payment capture reconciliation.
- **Session & CSRF Security**: Cookie-based server sessions (`withCredentials: true`), `x-csrf-token` attached for all state-mutating requests (`POST`, `PUT`, `PATCH`, `DELETE`).
- **Canonical Order Access & Guest Token Security**: `GET /api/orders/:orderId` with `X-Guest-Token` header for guest orders.
  - The raw guest token is retained only in ephemeral in-memory application state for the active guest checkout/tracking lifecycle and is transmitted exclusively through `X-Guest-Token`. It is not persisted in localStorage/sessionStorage, URLs, logs, telemetry, or API error payloads.
- **Available Quantity**: Public DTO `available_quantity` treated as read-only availability.
