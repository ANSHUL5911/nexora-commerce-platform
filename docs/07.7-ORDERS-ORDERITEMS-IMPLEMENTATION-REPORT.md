## 2. Objective
Implement the transactional Orders and OrderItems subsystem for the Nexora Commerce Platform. This module orchestrates customer checkout from persistent carts, constructs historical line item snapshots, executes server-authoritative integer monetary calculations (in INR paise), strictly coordinates Phase 07.6 inventory reservations within a single atomic PostgreSQL transaction, secures order data against IDOR exploits, enforces the internal order state machine lifecycle, and guarantees high-concurrency race protection (same-cart double checkout prevention and product lock ordering) without introducing future-phase payment gateways, Redis, or schema modifications.

---

## 3. Scope Implemented

1. **Sequelize Models & Relational Associations:**
   - Provisioned `Order` model mapping to `orders` (`user_id`, `status`, `subtotal_paise`, `shipping_fee_paise`, `total_paise`, `currency`, `shipping_address`, `billing_address`, `shipping_method`, `reservation_expires_at`, `payment_method`, `paid_at`, `notes`, `created_at`, `updated_at`).
   - Provisioned `OrderItem` model mapping to `order_items` (`order_id`, `product_id`, `product_name_snapshot`, `unit_price_paise`, `quantity`, `created_at`, `updated_at`).
   - Defined bidirectional Sequelize associations in `src/models/index.js`:
     - `User.hasMany(Order)` / `Order.belongsTo(User)` (`foreignKey: 'user_id'`, `onDelete: 'SET NULL'`)
     - `Order.hasMany(OrderItem)` / `OrderItem.belongsTo(Order)` (`foreignKey: 'order_id'`, `onDelete: 'CASCADE'`)
     - `Product.hasMany(OrderItem)` / `OrderItem.belongsTo(Product)` (`foreignKey: 'product_id'`, `onDelete: 'RESTRICT'`)
     - `Order.hasMany(InventoryReservation)` / `InventoryReservation.belongsTo(Order)` (`foreignKey: 'order_id'`, `onDelete: 'CASCADE'`)

2. **Immutable Historical Snapshots & Derived Line Totals:**
   - `OrderItem.product_name_snapshot` captures the exact product name at checkout time.
   - `OrderItem.unit_price_paise` captures the authoritative server price (`Product.price_paise`) at checkout time.
   - `OrderItem.line_total_paise` is strictly derived dynamically as `unit_price_paise * quantity` (never persisted as a separate database column).
   - `Order.subtotal_paise` is derived dynamically as `sum(items.line_total_paise)`.
   - Modifying active product names or prices post-checkout does not mutate historical order records.

3. **Integer Monetary Math & Safe JSON Serialization:**
   - All financial amounts (`subtotal_paise`, `shipping_fee_paise`, `total_paise`, `unit_price_paise`, `line_total_paise`) operate strictly in positive integer INR paise.
   - Zero floating-point arithmetic used.
   - Sequelize BigInt getters and DTO transformation layer (`toOrderDTO`, `toOrderItemDTO`, `toOrderSummaryDTO`) guarantee that all BigInts are converted to safe JavaScript numbers (within IEEE 754 Safe Integer limit $\le 2^{53}-1$) prior to JSON serialization, preventing `TypeError: Do not know how to serialize a BigInt`.

4. **Atomic Transactional Checkout Orchestration (`createOrderFromCart`):**
   - Coordinates all database operations in a single Sequelize managed transaction:
     1. Locks and reads the customer's active cart (`CartItem` rows with associated `Product` models).
     2. Validates cart non-emptiness, active product status (`!is_deleted`), and stock availability.
     3. Sorts order items by `product_id ASC` to prevent circular deadlocks with PostgreSQL foreign key `FOR KEY SHARE` row locks.
     4. Creates the `Order` record with initial status `PENDING_PAYMENT` and a 15-minute `reservation_expires_at` snapshot derived from database time.
     5. Creates all `OrderItem` snapshot rows in bulk.
     6. Invokes Phase 07.6 `inventoryService.reserveInventory` using the same transaction instance in ascending product UUID order.
     7. Clears all cart items from the customer's cart.
   - If any inventory reservation or item validation fails, the entire transaction rolls back completely (Order, OrderItems, reservations, inventory counter updates, and cart state).

5. **Same-Cart Double-Checkout Concurrency Protection:**
   - When concurrent checkout requests target the same customer cart, the first request acquires row locks and empties the cart within its transaction.
   - The competing losing request observes an empty cart upon lock acquisition and immediately fails with `EmptyCartError` (400 Bad Request) without creating partial or orphaned data.

6. **Order Lifecycle State Machine:**
   - Defined strict state transitions:
     - `PENDING_PAYMENT` $\rightarrow$ `PAID`, `CANCELLED`, `EXPIRED`
     - `PAID` $\rightarrow$ `PROCESSING`, `REFUNDED`
     - `PROCESSING` $\rightarrow$ `SHIPPED`, `CANCELLED`
     - `SHIPPED` $\rightarrow$ `DELIVERED`, `RETURNED`
     - `DELIVERED` $\rightarrow$ `RETURNED`
     - Terminal states: `CANCELLED`, `EXPIRED`, `REFUNDED`, `RETURNED`
   - Domain logic `orderService.transitionOrderStatus` enforces state machine transitions with PostgreSQL row locks (`SELECT ... FOR UPDATE`).
   - Customer-facing status manipulation is strictly forbidden (no status mutation endpoints exposed to customers in this phase).

7. **Anti-IDOR Security & REST API Surface:**
   - All customer order lookups and listings are strictly scoped to `req.user.id`.
   - Accessing another user's order ID returns a sanitized `404 Not Found` (`ORDER_NOT_FOUND`), preventing order existence enumeration.
   - Endpoints implemented:
     - `POST /api/orders` — Checkout from active cart (Session auth, Double-Submit CSRF, strict Zod validation).
     - `GET /api/orders/:id` — Retrieve customer order details with line items (Session auth, Anti-IDOR).
     - `GET /api/orders` — Deterministic paginated order history with status filter (Session auth, Anti-IDOR).
