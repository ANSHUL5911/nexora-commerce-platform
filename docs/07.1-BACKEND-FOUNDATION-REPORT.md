## 1. Scope

Phase 07.1 established the production-grade backend foundation infrastructure for the Nexora Commerce Platform. The implementation strictly focused on:
- Centralized environment configuration and fail-fast schema validation.
- PostgreSQL connectivity infrastructure and connection pooling via Sequelize.
- Request ID correlation middleware (`X-Request-Id`).
- Machine-readable structured JSON logging with sensitive field redaction.
- Centralized error handling architecture and standard error response formatting.
- Helmet security headers with Razorpay-compatible Content Security Policy (CSP).
- Strict origin CORS configuration supporting authenticated credentials.
- Reusable rate limiting infrastructure with standard 429 error responses.
- Application bootstrap refactoring (`src/app.js` and `server.js`) with graceful shutdown.
- Automated backend testing suite with Vitest and Supertest.

All domain business logic (user authentication, sessions, products, carts, orders, inventory reservations, Razorpay SDK calls, webhooks, and frontend code) was deliberately out of scope and preserved for future phases.

## 4. Configuration Architecture

The environment configuration is centralized in `src/config/env.js` and validated at boot time:
- **Zod Schema:** Normalizes data types, provides defaults matching the baseline, and extracts typed settings.
- **Fail-Fast Production Validation:**
  - `SESSION_SECRET`: Enforces $\ge 32$ characters; rejects placeholder patterns.
  - `GUEST_TOKEN_SECRET`: Enforces $\ge 32$ characters; rejects placeholder patterns.
  - `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, `RAZORPAY_WEBHOOK_SECRET`: Rejects placeholders in production.
  - `DB_PASSWORD`: Required in production.
  - `CORS_ORIGIN`: Forbids wildcards (`*`) with credentials in production.
- **Secret Safety:** Validation errors describe the specific constraint failure without printing actual secret values.

---

## 5. PostgreSQL Connection Architecture

- **Engine:** PostgreSQL 16+ via `pg` and `sequelize`.
- **Module:** `src/config/database.js`.
- **Connection Pool:** Configurable via `DB_POOL_MIN` (default 2) and `DB_POOL_MAX` (default 10).
- **SSL Configuration:** Environment-driven (`DB_SSL=true` enables SSL with `rejectUnauthorized: false` for cloud providers).
- **Health Verification:** `testDbConnection()` runs `sequelize.authenticate()`.
- **Shutdown:** `closeDbConnection()` gracefully closes connection pools during process termination.
- **Schema Management Policy:** `sequelize.sync()` is strictly avoided. Database tables and constraints will be provisioned exclusively via Sequelize CLI migrations in Phase 07.2.

---

## 6. Middleware Pipeline

The Express pipeline in `src/app.js` is assembled in strict dependency order:
1. **Request ID:** `requestId` middleware extracts safe `X-Request-Id` or generates UUIDv4.
2. **Security Headers:** `securityHeaders` (Helmet) sets frameguard, noSniff, and CSP.
3. **Strict CORS:** `corsMiddleware` verifies origin against whitelist with credentials enabled.
4. **Body Parsers:** `express.json({ limit: '100kb' })` and `express.urlencoded({ extended: true, limit: '100kb' })`.
5. **Request Logging:** `requestLogger` logs structured JSON metrics on response completion.
6. **Rate Limiting:** `generalLimiter` applied to `/api/` endpoints.
7. **Health / Application Routes:** `GET /api/health`, static `/images`.
8. **404 Handler:** `notFoundHandler` catches unmatched `/api` routes and returns standard JSON.
9. **Central Error Handler:** `errorHandler` formats all operational and internal errors into standard JSON.

---

## 7. Security Controls

- **No Wildcard CORS:** CORS origin is validated against `config.CORS_ORIGIN`. Wildcards are disallowed with credentials.
- **Helmet Headers:**
  - `X-Frame-Options: DENY`
  - `X-Content-Type-Options: nosniff`
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - Content Security Policy accommodating Razorpay standard checkout:
    - `script-src: 'self' https://checkout.razorpay.com`
    - `frame-src: 'self' https://api.razorpay.com`
    - `connect-src: 'self' https://api.razorpay.com https://lumberjack.razorpay.com`
- **Request Size Limiting:** JSON body parsing capped at `100kb` to prevent memory exhaustion attacks.
- **Bounded Request ID:** Ingested `X-Request-Id` must conform to `/^[a-zA-Z0-9_-]{1,64}$/`; invalid/malicious values are replaced with a cryptographic UUIDv4.

---

## 8. Error Architecture

- **Custom Hierarchy:** Standard errors extend `AppError` (`statusCode`, `code`, `isOperational`, `details`).
- **Standard Response Shape:**
  ```json
  {
    "error": {
      "code": "ERROR_CODE",
      "message": "User-facing message",
      "requestId": "uuid"
    }
  }
  ```
- **Information Leakage Prevention:** In non-development environments, internal stack traces and database details are omitted from HTTP response bodies.

---

## 9. Logging & Request-ID Architecture

- **Structured JSON Format:** Every log entry is serialized as single-line JSON with `timestamp`, `level`, `message`, `requestId`, and context.
- **Redaction Engine:** `redactSensitiveData` automatically redacts passwords, session secrets, tokens, cookies, authorization headers, card numbers, CVVs, and Razorpay signatures before logging.

---

## 10. Rate-Limiting Configuration

Configured in `src/middleware/rateLimiter.js`:
- **General Rate Limit:** 100 requests / 15 minutes / IP.
- **Authentication Rate Limit:** 5 requests / 1 minute / IP (`RATE_LIMIT_MAX_AUTH=5`).
- **Checkout Rate Limit:** 10 requests / 15 minutes / IP.
- **Guest Action Rate Limit:** 15 requests / 15 minutes / IP.
- **Standard 429 Response:** Returns JSON with code `RATE_LIMIT_EXCEEDED` and the request correlation ID.
