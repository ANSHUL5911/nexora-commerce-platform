## 1. Phase Overview & Scope

### 1.1 Phase Objective
Phase 07.4 establishes the high-performance, validated, secure, and production-grade Product / Catalog domain for the Nexora Commerce Platform. The implementation strictly adheres to the frozen specifications:
- `docs/01-PRD-v2.1.md`
- `docs/02-TRD-v1.2.1.md`
- `docs/05-BACKEND-SCHEMA-v1.0.md`
- `docs/06-IMPLEMENTATION-PLAN-v1.0.md`
- `docs/07.0-IMPLEMENTATION-BASELINE.md`
- `docs/07.2-DATABASE-MIGRATION-REPORT.md`

### 1.2 Implemented Scope (Phase 07.4):
- **PostgreSQL Sequelize Product Model (`src/models/Product.js`):** Exact mapping to frozen migration `003_create_products.cjs` with application-side UUID generation (`crypto.randomUUID()`), integer paise pricing (`price_paise`), non-negative constraints, and computed `available_quantity`.
- **Model Registry Integration (`src/models/index.js`):** Registered Product in the central model registry alongside User, Session, and AuditLog.
- **Product DTO Serializer (`src/modules/products/product.dto.js`):** Explicit allowlist serializer ensuring Sequelize model instances, raw DB metadata, or unexposed fields never leak to API consumers.
- **Strict Zod Input Validation (`src/modules/products/product.validation.js`):** Schema validation for query parameters (`page`, `limit` capped at 50, `category`, `search` bounded to 100 chars, `sortBy` allowlist, `sortOrder` allowlist, `inStockOnly` boolean) and UUIDv4 path parameters (`id`).
- **Product Repository (`src/modules/products/product.repository.js`):** Query layer with explicit column projections (`PRODUCT_PUBLIC_ATTRIBUTES`), parameterized search with LIKE/iLIKE wildcard escaping, deterministic secondary key sorting (`['id', 'DESC']`), and soft-delete exclusion (`is_deleted = false`).
- **Product Service Layer (`src/modules/products/product.service.js`):** Business logic and pagination math (`page`, `limit`, `total`, `totalPages`), mapping records through `toProductDTO`.
- **Product Controller (`src/modules/products/product.controller.js`):** HTTP request handlers for catalog listing and individual product retrieval with request ID correlation.
- **Product Route Registration (`src/modules/products/product.routes.js` & `src/app.js`):** Mounted public endpoints under `/api/products` integrated with general rate limiter, Helmet security headers, CORS, and centralized error handling.

### 1.3 Intentionally Excluded Scope (Non-Negotiable Boundaries):
- **Cart Domain:** Deferred to Phase 07.5.
- **Inventory Reservation Engine & Concurrency Locking (`SELECT FOR UPDATE`):** Deferred to Phase 07.6.

- **Frontend Redesign / UI Changes:** Deferred to Phase 07.14+.

## 2. Architecture & Data Flow

```
HTTP GET /api/products?page=1&limit=10&category=Outerwear&sortBy=price&sortOrder=asc
                                │
                                ▼
                   [ express.js Router ]
                                │
                                ▼
            [ Validation Middleware (Zod) ]
            - page: int >= 1
            - limit: int >= 1, max 50
            - sortBy: enum allowlist
            - sortOrder: enum allowlist
            - search: string <= 100 chars
                                │
                                ▼
            [ Product Controller (product.controller.js) ]
                                │
                                ▼
            [ Product Service (product.service.js) ]
            - Calculates totalPages
            - Orchestrates DTO shaping
                                │
                                ▼
            [ Product Repository (product.repository.js) ]
            - Parameterized Op.or / Op.iLike
            - Wildcard character escaping
            - is_deleted = false filter
            - Deterministic ORDER BY
            - Explicit attribute selection
                                │
                                ▼
            [ PostgreSQL DB (nexora_dev / nexora_test) ]
            - Hits indexed column 'category' / 'is_deleted'
                                │
                                ▼
            [ Product DTO (product.dto.js) ]
            - Computes available_quantity (stock - reserved)
            - Normalizes price_paise as integer number
            - Strips internal database attributes
                                │
                                ▼
            [ HTTP Response (200 OK) ]
            {
              "products": [ ... ],
              "pagination": { "page": 1, "limit": 10, "total": 4, "totalPages": 1 },
              "requestId": "req-uuid"
            }
```

## 4. Implemented API Endpoints

### 4.1 `GET /api/products`
- **Authentication:** None (Public)
- **Rate Limit:** 100 requests / 15 minutes per IP (via `generalLimiter`)
- **Query Parameters:**
  - `page` (optional integer, default 1, min 1)
  - `limit` (optional integer, default 10, min 1, hard max cap 50)
  - `category` (optional string, max 100 chars)
  - `search` (optional string, max 100 chars, searches name/description)
  - `sortBy` (optional enum: `price`, `price_asc`, `price_desc`, `name`, `created_at`, `createdAt`, `newest`, `oldest`)
  - `sortOrder` (optional enum: `asc`, `desc`, `ASC`, `DESC`)
  - `inStockOnly` (optional boolean / boolean string: `true` / `false` / `1` / `0`)
- **Success Response (200 OK):**
```json
{
  "products": [
    {
      "id": "d0000000-0000-4000-8000-000000000001",
      "name": "Monolith Architectural Coat",
      "description": "Structured wool-blend oversized coat tailored with sharp peak lapels.",
      "price_paise": 1899900,
      "category": "Outerwear",
      "image_url": "https://images.unsplash.com/photo-1539533018447-63fcce667883?auto=format&fit=crop&w=800&q=80",
      "stock_quantity": 1,
      "reserved_quantity": 0,
      "available_quantity": 1,
      "created_at": "2026-01-01T00:00:00.000Z",
      "updated_at": "2026-01-01T00:00:00.000Z"
    }
  ],
  "pagination": {
    "page": 1,
    "limit": 10,
    "total": 1,
    "totalPages": 1
  },
  "requestId": "22af156a-b195-422f-99ad-470b4380310e"
}
```
- **Error Responses:**
  - `400 Bad Request` (`VALIDATION_ERROR`): Malformed pagination, invalid category length, search string > 100 chars, or unallowlisted sort field/order.

## 5. Security & Invariant Verification

| Security Requirement | Implementation Detail | Verification Status |
|---|---|---|
| **SQL Injection Defense** | All database queries executed through parameterized Sequelize statements. LIKE/iLIKE wildcard characters (`%`, `_`, `\`) explicitly escaped in `product.repository.js`. | **PASS** (Tested via `' ; DROP TABLE products; --`) |
| **ORDER BY Injection Defense** | Strict enum validation in Zod; repository uses rigid switch-case allowlist mapping to database column identifiers with secondary sort by `id`. | **PASS** (Tested with malicious sort columns & SQL fragments) |
| **Sequelize Operator Injection** | Zod schema strictly validates types before passing to Sequelize; rejects object parameter injections (e.g. `category[$ne]=null`). | **PASS** (Tested with nested operator objects) |
| **Pagination Abuse & Resource Exhaustion** | Hard cap of 50 items maximum per page enforced via Zod schema (`max(50)`). Prevents unbounded `SELECT *` denial-of-service. | **PASS** (Tested with `limit=51` returning HTTP 400) |
| **Soft-Delete Information Leakage** | All repository queries strictly enforce `is_deleted = false`. Soft-deleted products return HTTP 404 on `GET /api/products/:id` and are excluded from catalog listings. | **PASS** (Tested with active vs archived items) |
| **Price & Inventory Tampering** | Public catalog APIs provide strictly read-only access. Direct model mutations via `req.body` are strictly blocked. Monetary amounts stored exclusively as integer paise (`BIGINT`). | **PASS** (Verified zero mutation endpoints in public catalog) |
| **Information Disclosure Sanitization** | `toProductDTO` strips internal Sequelize model properties and non-public database columns (`is_deleted`). Centralized error handler sanitizes stack traces in production. | **PASS** (Verified clean DTO and sanitized 404/400 errors) |
| **Deterministic Ordering** | All product queries enforce a stable secondary sort key (`['id', 'DESC']` or `['id', 'ASC']`) to eliminate non-deterministic pagination jumps across DB replicas. | **PASS** (Verified in repository and integration tests) |

## 6. Query Efficiency & Database Performance

- **Query Count Architecture:** Product listing performs one COUNT query and one paginated SELECT query through `findAndCountAll`. Product detail performs one SELECT query. No per-product/N+1 queries are executed.
- **Architectural Query Guarantees:**
  - Zero N+1 query patterns.
  - Strictly bounded pagination (hard capped at maximum 50 items per page).
  - Explicit attribute selection (`PRODUCT_PUBLIC_ATTRIBUTES`) eliminating `SELECT *`.
  - Efficient index-backed filtering where applicable (`category`, `is_deleted`).
- **Dynamic Stock Computation:** `available_quantity` calculated dynamically on the server via `(stock_quantity - reserved_quantity)`, preventing persistent derived counter inconsistencies.

## 9. Schema Reconciliation & Architectural Boundaries

### 9.1 Frozen Specification vs Database Index Discrepancy (`idx_products_fulltext`)
- **Frozen Specification Reference:** `docs/05-BACKEND-SCHEMA-v1.0.md` (Section 15) and `docs/02-TRD-v1.2.1.md` indicate `idx_products_fulltext` as a PostgreSQL GIN full-text index on `(to_tsvector('english', name || ' ' || description))`.
- **Actual Database & Migration State:** Inspection of the authoritative Phase 07.2 migration `003_create_products.cjs` and PostgreSQL schema confirms `idx_products_fulltext` does not exist. Only `idx_products_category` and `idx_products_is_deleted` were created.
- **Resolution & Policy:** Phase 07.2 migrations are frozen and cannot be silently reopened or modified in Phase 07.4. Current Phase 07.4 implementation safely uses parameterized `ILIKE` on `name` and `description` with wildcard escaping (`%`, `_`, `\`).
- **Strict Invariant:** No `pg_trgm`, GIN indexes, Elasticsearch, Redis, vector search, or AI search infrastructure is introduced.

### 9.2 Deferred Boundaries
- Administrative product mutation endpoints (`POST/PUT/DELETE /api/admin/products`) remain deferred to Phase 07.13.
